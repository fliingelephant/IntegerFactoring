## 1. Stable-modulus arithmetic

The displayed factorization and stable-class certificate are correct:

    47 times 59 = 2773
    gcd(46,58) = 2
    A = 46 / 2 = 23
    B = 58 / 2 = 29
    gcd(23 times 29, 2772) = 1

This matches the stated P98 stable example. The P98 label is context for the
chosen modulus. It is not used by the search code.

## 2. Canonical-inverse relations

The first relation is exact:

    3 times 1849 = 5547 = 1 + 2 times 2773
    5547 = 3 times 43 squared

The second relation is exact:

    842 times 2526 = 2126892 = 1 + 767 times 2773
    2126892 = 3 times 842 squared
            = 2 squared times 3 times 421 squared

All endpoints are in the interval from 2 through 2772. Congruence to one
and membership in that interval prove that 1849 and 2526 are the least
positive inverses of 3 and 842, respectively.

## 3. Public square-normalized basis

The certificate based on the public basis (3,43,842) is valid:

    gcd(5547,2126892) = 3
    5547 / 3 = 1849 = 43 squared
    2126892 / 3 = 708964 = 842 squared

The pairwise gcds among 3, 43, and 842 are all one. The fact that 842 is
composite does not invalidate a gcd-free basis. The certificate needs
pairwise-coprime integer blocks, not prime blocks. It therefore obtains the
exact columns

    u1 = (1,2,0)
    u2 = (1,0,2)

and both reduce modulo two to the same nonzero column (1,0,0).

The optional prime expansion is also correct. Since 842 = 2 times 421 and
421 is prime, the basis (2,3,43,421) gives columns

    (0,1,2,0)
    (2,1,0,2),

which both reduce to (0,1,0,0). The discovery code computes this prime
expansion only after a pair has passed the square-product and proper-factor
tests. It is not a selection oracle.

## 4. Presentation and deletion claims

Against the empty matrix, either nonzero one-column matrix has rank one and
zero-dimensional kernel. After retaining the first column, the second
column is equal to it modulo two. The two-column matrix has rank one and
kernel generated by (1,1).

Deleting the first column leaves the same nonzero second column against the
empty matrix. Its kernel is again zero. Thus deletion really loses this
specific later closure. The claim concerns the explicit retained
presentation; it does not claim that abstract subgroup data is lost.

## 5. Induced root and factor

The dependency gives

    R = 3 times 43 times 842 = 108618
    R squared = 11797869924 = 5547 times 2126892
    R mod 2773 = 471
    gcd(R - 1,2773) = 47
    gcd(R + 1,2773) = 59

The equivalent direct comparison is also exact:

    gcd(842 - 43,2773) = 47
    gcd(842 + 43,2773) = 59

This equivalence is decisive for scope. The witness is precisely a
congruence-of-squares collision between two square roots of the same unit.
The candidate states this explicitly.

The independent full-range enumeration reproduced:

    raw values in 2 through 2772                 2771
    units                                         2667
    nonunits                                       104
    unique exact canonical relation values         634
    nonsquare relation values                       631

The nonunit count also follows directly. There are 58 positive multiples
of 47 below 2773 and 46 positive multiples of 59 below 2773. None is a
multiple of 2773, so the total is 104.

The three square relation values have sorted indices 51, 567, and 633.
The sorted list begins with

    index 0: P = 2774, endpoints (2,1387)
    index 1: P = 5547, endpoints (3,1849)

and index 306 is

    P = 2126892, endpoints (842,2526).

These are zero-based indices in the unfiltered 634-element list of unique
relations. The source assigns relation_index before it tests and skips
individual squares. If one instead renumbers the 631-element nonsquare-only
list, the corresponding positions are 1 and 305 because square index 51
precedes the second witness relation. RESULT.md says that 1 and 306 are
indices in the declared sorted list, so its wording is correct. They must
not be read as positions in a renumbered filtered list.

Independent nested enumeration of nonsquare pairs found no earlier square
product. The first square-product pair is exactly (1,306), and its root
already gives the proper factor 47.

The eligible-pair count 934 is also consistent with the ordering. Index
zero tests 630 later nonsquare values. Index one then tests 304 eligible
values through index 306 because square index 51 is skipped. Hence

    630 + 304 = 934.

The claimed minimality is therefore correct under the declared ordering.
It is not minimality across other orderings or moduli, and no such broader
claim is made.

## 7. Hidden-factor and completeness audit

The source contains no supplied factor of N. Candidate generation uses N,
range enumeration, public gcds, modular inversion, and exact integer
arithmetic. Deduplicating equal P values is complete because equal exact
integers have the same parity column. Sorting and early stopping preserve
the stated first-success semantics.

There is one essential limitation. The first nonunit in the range is
g = 47, and its public gcd with N is already the proper factor 47. A later
nonunit similarly exposes 59. The source completes the entire raw scan
before it searches relation pairs, so these factors are computationally
encountered before the reported witness is selected. The code does not use
their values: it only increments the nonunit count and continues.

This is not hidden-factor leakage into witness selection. It does mean that
the run cannot demonstrate an advantage for relation accumulation over
ordinary trial gcds. RUN_MANIFEST.md states this exact point: a real
factorer would stop at a nonunit gcd, while this experiment continues only
to test the saturation mechanism.

The proper-factor gcd is evaluated before witness factorization and
primality certification. The control flow therefore prevents the
certificate-only trial factorization from affecting pair acceptance.
