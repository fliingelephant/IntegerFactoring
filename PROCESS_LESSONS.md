# Process lessons

- State the public source, the decoder, and the final missing lemma as separate
  items before an experiment starts.
- Prove useful probability and evaluation cost separately. A large pool of good
  events is not useful if finding or evaluating one still takes too long.
- Use both a hostile audit and a blind reconstruction. They find different
  errors, especially hidden assumptions and claims with too much scope.
- Distinguish actual ring values from formal coordinate objects. Remove repeated,
  constant, and degenerate cases with simple linear tests before using a larger
  algebra model.
- Establish independence before using a decomposition argument. Similar-looking
  local choices can still share one hidden choice.
- Before a long computer run, use a small named dry run to test input and output
  serialization. This prevents a tool-format error from wasting the full run.
- Ask delegated workers to write a narrow artifact early. Interrupt a stalled
  attempt before it consumes a full research cycle.
- Keep durable ledgers, exact file hashes, and a precise next action. This makes a
  shutdown and restart safe.
- For retained-relation methods, normalize repeated exact values before counting
  rank or nullity. Measure the image of the decoded root map, not the number of
  records.
- Do not discard every nonclosing relation. One such relation can be the first
  half of a later circuit. Cap explicit state with proved lossless compression,
  not with a local no-progress label.
- Degree-one peeling is lossless only after the relation batch is frozen. A
  later column can reuse a row that is private now. Use peeling as a decoder
  preprocessor, not as a permanent online deletion rule.
- A residual class is not a mechanism. Before assigning an origin to a
  selected circuit, test the proposed explanation on the complete generated
  reservoir and state a public comparison rule.
- Residue deduplication and exact-value deduplication are different. Audit the
  map between their coordinates. Prove that its kernel has only global roots
  before transferring a useful dependency.
- Append monotonicity removes a hidden stopping rule. It does not remove a
  source choice that was made after earlier experiments. Record these two
  forms of postselection separately.
- A sparse expression DAG can replace dense dependency masks. It does not make
  all decoder memory linear, and it does not remove factor-assisted endpoint
  decomposition from discovery.
- Kernel nonzero and useful-root image nonzero are separate claims. A rank
  defect gives possible relations. It does not prove that a terminal gcd will
  split the input.
- Once the frozen batch has a complete factor-free decode, splitting its
  blocks cannot reveal a missing old dependency. A split is real feedback only
  if it changes the future relation source.
- After several finite positives, search for a clean null at a larger size.
  This is more informative than adding similar positives when the source menu
  can still be large compared with the modulus.
- Preregister the condition that opens an adaptive follow-up. If the fixed
  source already succeeds, do not run feedback and call it a rescue.
- A kernel can contain hundreds of thousands of global-root directions before
  its first useful direction. Track the normalized-root image, not only rank
  defect or nullity.
- After repeated finite rescues, move the main effort to an exact source law or
  a stable counterfamily. More cases improve confidence, not the theorem.
- Abstract subgroup growth is not enough when bare $N$ already gives the
  full unit group. Track whether feedback creates a short, named integer
  presentation that the next source can use.
- One permanently private row does not block the decoder. Peel its column and
  test the remaining kernel and normalized-root image.
- For an append-only source, one verified successful prefix certifies success
  of the full source. Stop after the certificate when a no-stop run consumes
  too much memory; do not require terminal counts that add no theorem value.
- Test feedback only after the complete static source is null. A restricted
  state can make an ordinary static relation look like a feedback rescue.
