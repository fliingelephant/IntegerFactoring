## 1. Frozen finite question and deliberate semantic changes

For each imported public odd modulus, build one fixed `U union POWER`
two-curve bank, perform one simultaneous saturated peel, and use F271 V2 on
the at-most-64-row residual. Does the complete structural complement outside
the support-at-most-two span have a non-global normalized-root image?

D09 deliberately differs from D05--D08 in four ways.

1. It performs one peel round, not a fixed-point peel.
2. It uses F271 V2, not the D08 quadratic block terminal.
3. It performs no full-bank unordered-pair control or support-two scan.
4. It reuses a pinned corpus and does not generate semiprimes.

These are question and resource changes, not silent optimizations. A D09
structural hit is strict only relative to generation-stage factors and the
complete low-support image. It is not claimed to survive an omitted
quadratic coordinate-control scan.

## 3. Exact deterministic curve source

The 64-bit master seed is

`0x0F265D09C0DEC0DE`.

All `uint64_t` arithmetic below wraps modulo `2^64`. Define

```text
mix64(x):
    x = x + 0x9e3779b97f4a7c15
    x = (x xor (x >> 30)) * 0xbf58476d1ce4e5b9
    x = (x xor (x >> 27)) * 0x94d049bb133111eb
    return x xor (x >> 31)

seed_key(x_0,...,x_t):
    h = 0x0F265D09C0DEC0DE
    for x in order: h = mix64(h xor mix64(uint64(x)))
    return h

Rng.next():
    state = mix64(state)
    return state
```

There is no discarded warm-up draw. Split codes are zero for discovery, one
for heldout, and two only for preflight. Factor bits are the actual values,
not their ranks. Shape codes are as in Section 2.

Curve zero has mode/domain `(U,100)` and curve one has `(POWER,108)`. Its
single stream across all attempts starts from

```text
seed_key(0xEC265D09, split, factor_bits, shape, index, domain, curve_id).
```

`random_below(n)` is exact rejection sampling. For `n>1`, set
`b=bitlen(n-1)`. One attempt consumes one 64-bit draw when `b<=64` and two
draws otherwise, concatenates the second draw above the first, masks to `b`
bits, and accepts exactly when the result is below `n`. It makes at most 128
attempts. Exhaustion throws `RESOURCE_REJECT_RANDOM_BELOW_CAP`. No modulo-
bias substitution is permitted.

Each curve stream has exactly 32 proposal slots. A `U` proposal draws, in
order,

```text
A = 1 + random_below(N-1), x_0 = random_below(N),
y_0 = random_below(N).
```

A `POWER` proposal draws only

```text
s = 1 + random_below(N-1)
```

and uses the algebra file's deterministic assignments. Compute `B`, then the
nonnegative integer `delta=4A^3+27B^2` without first reducing `delta` modulo
`N`, and compute `d=gcd(delta,N)` before testing `B`. Apply this total order:

1. if `1<d<N`, journal `CURVE_DISCRIMINANT` as a sticky terminal generation
   factor and stop the bank;
2. if `d=N`, reject the degenerate proposal and consume its proposal slot;
3. if `d=1` and `B=0`, reject the inadmissible proposal and consume its
   proposal slot;
4. if `d=1` and `B!=0`, apply the one bank-local cross-mode duplicate check;
   a duplicate consumes its proposal slot, and a nonduplicate is clean.

Thus a proper discriminant factor wins even when `B=0`. Exhausting all 32
slots is `RESOURCE_REJECT_CURVE_ATTEMPTS`.

The first proposal to pass these three screens is irrevocably accepted. Its
complete scalar orbit is then attempted. An orbit factor, infinity, global
exception, row-root failure, or source cap stops or skips the bank. It does
not consume another curve-proposal slot and it does not resume the proposal
loop.

The evidence nonce for a bank is

```text
low32(seed_key(split, factor_bits, shape, index)).
```

It has no arithmetic effect.

## 4. Mandatory bank chronology

The evaluator authenticates both public corpora before any bank. It then
processes discovery and its independent replay to completion, followed by
heldout and its independent replay. Within a split, take consecutive chunks
of at most eight canonical banks. Generate and peel a chunk with at most
eight workers, join it, place results back in canonical order, then run the
chunk's decoders through the work-conserving reservation batches in Section
7. Commit core records in canonical order. Worker completion order never
changes a byte or a reservation decision.

For every bank, preserve these logical phases.

1. Authenticate the public corpus record and initialize its sticky journal.
2. Generate the complete `U` curve and all `K` affine rows.
3. Generate the complete `POWER` curve and all `K` affine rows.
4. Commit the curve and row stream digest. A direct factor stops here; a
   full affine or row-root gcd gives `BANK_SKIP`; a source cap gives
   `RESOURCE_REJECT`.
5. Build one full row product and execute exactly one simultaneous saturated
   peel round. Commit every row's `g_i,b_i`, square bit, and survivor bit.
6. If the residual is empty, commit a verified zero kernel without taking a
   decoder reservation. If it has 1 through 64 rows, request one F271
   reservation under Section 7. If it is larger, reject it.
7. Run the complete F271 V2 decoder, low basis, complement, and every basis
   root classification. Embed masks in the original 320-coordinate order.
8. Atomically commit the complete core and its hashes.
9. Leave the bank available for the later diagnostic pass.

A later phase never feeds a factor into an earlier or later arithmetic
phase. A relation factor does not stop the remaining basis classifications.
An invariant failure aborts the split and produces no finite label.

The independent replay reads only committed public rows and core records. It
regenerates both scalar orbits, checks the row laws, recomputes the one-round
peel, reruns every completed F271 decoder, reconstructs both bases and all
roots, and requires byte-identical counters and stream digests. It does not
replay post-commit diagnostic retention.

After both split cores and both replays join, commit the finite decision from
the core only. Then run one diagnostic pass over discovery followed by
heldout, each in canonical bank and task order, under the common 900-second
diagnostic cap. After that process joins, the private-label auditor may run.
Neither diagnostics nor label audit can revise the committed finite
decision.

## 5. Closed factor journal and status semantics

The complete factor-class enum has six values:

| Code | Class | Call site |
|---:|---|---|
| 0 | `CURVE_DISCRIMINANT` | pre-admissibility proposal discriminant screen |
| 1 | `FACTOR_X_SIGN` | affine equal-`x` signed-`y` branch |
| 2 | `AFFINE_DENOMINATOR` | affine denominator screen |
| 3 | `ROW_ROOT` | prospective row-root screen |
| 4 | `LOW_BASIS` | normalized-root signed gcd for `L` |
| 5 | `STRUCTURAL_Q` | normalized-root signed gcd for `Q` |

The factor phases are `CURVE=0`, `AFFINE=1`, `ROW=2`, `LOW=3`, and
`STRUCTURAL=4`. The signed side codes are `NONE=0`, `MINUS=1`, and
`PLUS=2`. Put `NO_CURVE=NO_ROW=65535`. Original row IDs are `0,...,K-1`
on curve zero and `K,...,2K-1` on curve one. The five mask words use
little-index order: original row `i` is bit `i mod 64` of word
`floor(i/64)`.

Every event is one LF-terminated, tab-separated line with exactly these 15
fields:

```text
bank_event_ordinal phase class side curve row_1 row_2 mask_present
mask_0 mask_1 mask_2 mask_3 mask_4 g_hex bank_nonce
```

The line break shown above is editorial; the serialized record is one line.
Decimal fields have no leading zero. Each mask word is exactly 16 lower-case
hexadecimal digits. `g_hex` is lower-case hexadecimal without a prefix or
leading zero. `bank_nonce` is unsigned decimal. The complete coordinate
rules are:

| Class | Phase | Side | Curve and rows | Mask |
|---|---:|---|---|---|
| `CURVE_DISCRIMINANT` | 0 | `NONE` | proposal curve; two `NO_ROW` | absent; five zero words |
| `FACTOR_X_SIGN` | 1 | reached `MINUS` or `PLUS` gcd | common curve; increasing distinct operand IDs | absent; five zero words |
| `AFFINE_DENOMINATOR` | 1 | `NONE` | common curve; increasing IDs, repeated for doubling | absent; five zero words |
| `ROW_ROOT` | 2 | `NONE` | prospective row curve; row ID then `NO_ROW` | absent; five zero words |
| `LOW_BASIS` | 3 | reached `MINUS` or `PLUS` gcd | `NO_CURVE`; two `NO_ROW` | present; exact nonzero five-word mask |
| `STRUCTURAL_Q` | 4 | reached `MINUS` or `PLUS` gcd | `NO_CURVE`; two `NO_ROW` | present; exact nonzero five-word mask |

Schema validation and the literal 192-byte event-line cap are checked before
the sticky journal mutates. A worker retains the complete at-most-129-line
bank stream so the scheduler can hash packet events in canonical bank order.
The event stream is not written in full; the core stores its count, digest,
and first witnesses.

Only a verified integer `g` with `1<g<N` and `N mod g=0` enters the journal.
Generation stops at its first event, so it contributes at most one event.
The dimensions of `L` and `Q` sum to at most 64, and each classified vector
has two signed gcds. Thus one bank has at most 129 events and the packet at
most

\[
 468\cdot129=60{,}372.
\]

An attempted 130th bank event or 60,373rd packet event is an invariant
failure, not a truncation. Every event is streamed into a SHA-256 digest.
The bank summary retains the first overall event and the first event of each
class. `observed_factor`, count, first witnesses, and digest are sticky
through a later resource or core-writer rejection.

Exactly one bank status is chosen by this precedence:

1. `RESOURCE_REJECT` for any recoverable bank-local source, residual,
   reservation, decoder-counter, counted-arena, record-rendering, or core
   writer cap reached before core commit;
2. `ELIGIBLE` after the complete core commits, whether or not a relation
   factor occurred;
3. `DIRECT_STOP` after a generation factor stopped an otherwise nonresource
   bank;
4. `BANK_SKIP` after a full gcd, global infinity, or unresolved global
   affine exception made the orbit incomplete.

The serialized status codes are `ELIGIBLE=0`, `DIRECT_STOP=1`,
`BANK_SKIP=2`, and `RESOURCE_REJECT=3`; precedence, not numeric order,
selects the code.

There is no corpus shortfall status because the imported retained rows are
fixed. A missing, duplicate, malformed, or hash-mismatched corpus row aborts
the split. Authentication, an invariant failure, packet-output overflow,
cgroup enforcement, or the common runner deadline aborts the run and
produces no finite label. Post-commit diagnostic timeout, detail omission,
or diagnostic writer failure never changes the already committed
`ELIGIBLE` status.

## 7. Atomic F271 reservation ledger

The literal production cap is

```text
F271_GCD_CALLS_PACKET_MAX = 8,388,608
```

It counts only the scalar gcd calls in the F271 refinement and terminal
coprimality theorem. Source, peel, relation signed gcds, diagnostics, and the
independent replay have separate counters. The replay has its own identical
8,388,608-call cap, so search plus replay execute at most 16,777,216 such
calls.

Every nonempty residual requests a reservation of 91,111 calls before its
decoder starts. Empty residuals need no reservation. At a batch boundary
`A=0`. Scan banks in canonical order, committing empty residuals immediately
and granting consecutive nonempty residuals until eight reservations are
active or the next reservation would not fit. Let `C` be committed calls and
`A` active reserved calls. A reservation is granted only when

```text
C + A + 91,111 <= 8,388,608.
```

Within a worker, the next scalar gcd is forbidden when its bank-local count
would exceed 91,111. At bank completion, commit its actual count and return
the unused reservation. A rejected or failed decoder commits every call it
actually made before returning the unused balance. The invariant

```text
committed + active reservations <= 8,388,608
```

is checked before and after every batch transition and is serialized.

If the next reservation does not fit while `A>0`, launch the already granted
batch, join every worker, commit actual call counts in canonical bank order,
set `A=0`, and retry that same next bank. Mark a nonempty residual
`RESOURCE_REJECT_PACKET_GCD_RESERVATION` without entering F271 only when
`C+91,111>8,388,608` at `A=0`. Since `C` never decreases, every later
nonempty residual is then rejected when reached, but a later empty residual
can still be eligible. This work-conserving rule is independent of worker
completion order. A reservation rejection never counts as a null.

```text
F271_TREE_NODE_UPDATES_PACKET_MAX     54,156,366
F271_EXPONENT_COORD_UPDATES_MAX      313,174,656
F271_RECONSTRUCTION_INCIDENCES_MAX    10,812,672
F271_TERMINAL_BLOCKS_PACKET_MAX          877,500
```

The first six derived caps use

\[
 E\le C/2,\qquad T\le C/12,
 \qquad E+T\le7C/12,
 \qquad 2T+3E\le5C/3,
\]

with `C=8,388,608`, plus at most `468*64=29,952` residual-row insertions.
They are direct runtime checks even though the inequalities prove them for
completed decoders.

Replacement and final block sorting use a source-owned bottom-up stable
mergesort, not an implementation-dependent `std::sort`. It makes at most
`k*ceil(log2(k))` integer comparisons on a `k`-item list. Every replacement
item is a nonunit pairwise-coprime divisor of one at-most-361-bit old block,
so the 58-prime certificate gives `k<=57` and `ceil(log2(k))<=6`. F271 gives
at most `E+T` replacement items. Therefore the exact registered packet caps
are

```text
F271_REPLACEMENT_COMPARISONS_MAX  29,360,124 = 6*4,893,354
F271_FINAL_COMPARISONS_MAX         9,652,500 = 468*1,875*11
F271_BLOCK_COMPARISONS_MAX        39,012,624
```

Every stored exponent is checked in `uint16_t` and must be at most 360.

Crossing any independent counter rejects the current bank before the next
operation and returns the unused reservation. A mismatch with the F271
theorem is also an invariant failure when it falsifies an asserted exact
identity, reconstruction, parity equation, or call formula.

## 8. Complete basis records and finite labels

For each eligible bank, report exact singleton and support-two counts from
signature classes, the canonical low basis `L`, canonical structural
complement `Q`, and every basis root class. Do not enumerate all
support-two masks. `dim(L)+dim(Q)<=64`, so at most 64 basis records exist per
bank and 29,952 across the packet.

A bank has a `decoder_strict_structural_hit` exactly when:

1. no generation factor was observed;
2. its complete core is eligible;
3. every low-basis image is global; and
4. at least one `Q` basis image is non-global.

A `low_hit` is a non-global image in `L`. It is a valid factor but not a
structural-complement hit. A structural factor on the non-global-low branch
is recorded as `STRUCTURAL_ONLY_LOW_IMAGE` and is not decoder-strict.

The heldout decision is chosen by this precedence.

1. `FINITE_STRUCTURAL_POSITIVE_SIGNAL` if at least two decoder-strict
   structural-hit banks occur in at least two heldout factor-bit cells.
2. `FINITE_OTHER_FACTOR_SIGNAL` if any heldout factor was observed but the
   structural-positive gate failed.
3. `FINITE_NULL_SIGNAL` if all null clauses below hold.
4. `FINITE_MIXED_OR_INCONCLUSIVE` otherwise.

The null clauses are:

- zero sticky factor events in all 288 intended heldout slots;
- every eligible bank completed F271 when nonempty, both bases, and all root
  classifications;
- `quotient_defined=true` and every `Q` image global in every eligible bank;
- at least 260 eligible heldout banks; and
- at least 22 eligible banks in each of the 12 heldout factor-size/shape
  cells.

A direct stop, bank skip, residual rejection, reservation rejection, core
record rejection, or other ineligible bank is governed only by these
coverage floors. An observed factor in a later rejected bank still prevents
null. No discovery count enters a heldout threshold. Post-commit diagnostic
state is not a finite-label input.

## 9. Diagnostic task and retention contract

After core commit, choose the first eight canonical `Q` vectors with support
at most 16. For each, generate all same-curve pair and anchored-third tasks
defined in the algebra. The total key is

```text
(split, factor_bits_rank, shape, index, basis_ordinal, task_kind,
 curve, pair_row_1, pair_row_2, third_row).
```

`PAIR=0`, `ANCHORED_THIRD=1`, and a pair uses `third_row=65535`. Generate and
hash tasks in this lexicographic order. Here split, shape, and row codes are
the numeric codes already fixed; `factor_bits_rank` is the zero-based rank
in `(12,16,20,24,32,40,48,56,60)`; and `basis_ordinal` is zero-based in
canonical `Q` order before the support filter. Every task advances complete
aggregate counters and a SHA-256 stream. Retain only the first 16 detail
records per bank. An oversize detail is omitted and counted without changing
the complete task stream.

The task-stream bytes are LF-terminated tab-separated lines. Decimal fields
have no leading zero; integer values use lower-case hexadecimal without a
prefix or leading zero; Boolean fields are `0` or `1`. A pair line is

```text
P key_fields H_hex d_tan_hex d_chord_hex d_disc_hex
```

and an anchored-third line is

```text
A key_fields sum difference twice thrice product equal_v2
chord_checked chord_zero
```

The displayed wraps are editorial; each serialized record is one line.
`key_fields` expands to the ten decimal fields of the displayed total key.
`chord_checked` is one exactly when the cached `d_chord>1`; `chord_zero` is
then the truth value of the algebra's congruence and is zero when no check
occurs. Aggregate counters include total tasks and true counts for all eight
Boolean fields.

The exact packet maxima are:

\[
 468\cdot960=449{,}280\text{ pair tasks},
\]

\[
 468\cdot13{,}440=6{,}289{,}920
 \text{ anchored-third tasks}.
\]

Each pair task computes one cached `gcd(a_i,a_j)` and three derived gcds, so
diagnostics make at most `4*449,280=1,797,120` scalar gcd calls. They make at
most `3*449,280=1,347,840` coordinate multiplications for `H`, exactly six
index-predicate evaluations per anchored task, hence at most 37,739,520, and
at most 6,289,920 chord congruence remainders.

The diagnostic phase has one 900-second wall cap. On timeout, record the
completed prefix count, prefix digest, exact next task key, and `TIMEOUT`.
The unfinished suffix is not represented as exhaustive. Diagnostic failure,
timeout, truncation, or oversize omission cannot change the committed core
or finite label.

## 10. Exact output and memory caps

Every complete mathematical stream has a counter and SHA-256 digest. The
independent replay reconstructs the decoder from public row records, so D09
does not serialize every opaque block or every support-two hit.

The final category caps are:

| Category | Exact byte cap |
|---|---:|
| 468 bank summaries at 16,384 bytes | 7,667,712 |
| 122,112 row-plus-peel records at 512 bytes | 62,521,344 |
| 64 basis records per bank at 512 bytes | 15,335,424 |
| 16 diagnostic details per bank at 1,024 bytes | 7,667,712 |
| global summaries and factor certificates | 8,388,608 |
| imported corpus and label copies | 8,388,608 |
| all preflight artifacts | 67,108,864 |
| source, binary, logs, manifests, and hashes | 33,554,432 |
| **total** | **210,632,704** |

A row record does not repeat `N,A,B`; those values occur in the bank summary.
It stores fixed IDs and hexadecimal `u,v,a,carry,g_i,b_i` plus square and
survivor bits. For `N<2^120`, the maximum digit counts are 30 for `u,v`, 91
for each of `a,g_i,b_i`, and 61 plus a sign for `carry`. The literal
512-byte record cap therefore has explicit slack.

A basis record stores a five-word original-row mask, class and ordinal,
exact-root residue modulo `N`, supplied root, normalized root, both signed
gcds, and root class. Every residue or factor has at most 30 hexadecimal
digits. The full positive integer root is reconstructed by replay and is not
duplicated in output. A reported factor certificate is never a truncatable
detail.

The complete factor-event stream is retained only in the bank temporary,
not as an output category. Its maximum is `129*192=24,768` bytes. The
largest one-bank temporary is therefore

```text
16,384 + 320*512 + 64*512 + 16*1,024 + 129*192
= 254,144 bytes.
```

At most 64 completed temporaries await canonical commit. Atomic replacement
may duplicate the 64 MiB preflight category. Thus the experiment-directory
peak is at most

\[
 210{,}632{,}704+64\cdot254{,}144+67{,}108{,}864
 =294{,}006{,}784\text{ bytes}.
\]

Every record is rendered in memory and checked before append. A required
bank summary, row, basis record, digest, or factor witness overflow rejects
the bank. Only diagnostic details may be omitted. The per-file cap is 128
MiB and the complete output cap is the displayed total.

Production uses at most eight workers. Each worker has a counted 128 MiB
arena, including rows, products, the F271 tree, exponent vectors, roots, and
one-bank serialization. Writer and scheduler storage is capped at 256 MiB.
The static live allowance is therefore 1.25 GiB. Measured whole-process RSS
must remain at most 3.5 GiB.

## 12. Runner and host resource contract

The complete runner has one 14,400-second wall deadline beginning before
authentication and compilation. It uses at most eight workers and `nice 15`.
Before every phase it rejects an incompatible experiment process, load above
twice the visible CPU count, less than 8 GiB available memory, or less than 4
GiB free disk.

The exact runner requires a writable cgroup-v2 subtree with:

```text
memory.max       = 4294967296
memory.swap.max  = 0
pids.max         = 128
```

The runner records `memory.peak`, installs the main process in
`cgroup.procs`, and uses `cgroup.kill` on timeout or abnormal finalization.
Every child also inherits a 4 GiB `RLIMIT_AS`, a 128 MiB file-size limit,
and the common deadline. Measured peak RSS must be at most 3.5 GiB.

If the target lacks this writable interface, D09 stops before compilation.
Replacing cgroup enforcement by `RLIMIT_AS`, sampled RSS, or another
mechanism is a workflow and evidence change. It needs explicit user approval,
a new immutable version, and a fresh hostile audit; it cannot occur silently.

All paths are explicit absolute target paths below one new run directory.
The process firewall authenticates executable, command line, current working
directory, PID/start-time ancestry to PID 1, and the absence of another
F265/F271 evaluator or generic experiment runner before each phase. The
future source and runner audit must freeze its exact byte schema and caps.

## 13. Finite interpretation and hostile audit gate

D09 is a large finite heuristic search, not a success theorem. Reusing the
F268 corpus avoids semiprime-generation cost but weakens corpus novelty. The
one-round peel can make nearly all banks cheap, but the D02 private-pivot
observation is motivation only and does not enter a denominator or runtime
formula.

Before source is written, a fresh no-context hostile theory reviewer must
try to kill at least:

- every import hash and the absence of implicit D05--D08 composition;
- the `U union POWER` source, exact RNG stream, 128-attempt sampler, 32 curve
  proposals, duplicate rule, and complete-orbit semantics;
- the one-round saturation valuation proof, simultaneous deletion, kernel
  isomorphism, and unchanged normalized roots;
- the exact F271 V2 import, 64-row boundary, empty-core case, signatures,
  low span, complement, and root classification;
- the deliberate removal of all-bank pair controls and the narrowed meaning
  of decoder strictness;
- all corpus hashes, filter counts, canonical order, replay chronology, and
  factor-label process firewall;
- the atomic 91,111-call reservation protocol, packet cap, returned tokens,
  later empty-bank eligibility, and every derived counter;
- the closed six-class sticky factor journal and 129-event proof;
- heldout positive/null precedence and every all-slot or eligibility
  quantifier;
- diagnostic total order, same-curve provenance, caps, timeout prefix, and
  noninterference;
- every record width, category sum, temporary/output/disk calculation, and
  memory allowance;
- every preflight fixture, deliberate double charge, projection coefficient,
